## Unit of analysis — read this before Phase 1 closes

The source paper hit the same `patient_nbr`-repeats issue and resolved it deliberately: because repeated encounters from the same patient aren't statistically independent (a requirement for logistic regression), they kept **only the first encounter per patient**, and separately excluded any encounter ending in hospice discharge or death. That took their working set from 101,766 encounters down to 69,984.

Decide explicitly whether to follow this same approach for Phase 4 (the logistic regression) — it's the methodologically correct choice for that model, but it means Phase 1-3's descriptive/SQL work could still reasonably use the full encounter-level set, since readmission-rate-by-diagnosis type descriptive queries don't carry the same independence assumption. Document whichever choice you make, and be consistent about which dataset version (full vs. first-encounter-only) feeds each phase.

## ICD-9 diagnosis grouping — use this, don't invent your own

The source paper's Table 2 gives the exact clinical category scheme used to bucket `diag_1`'s 848 raw ICD-9 codes into interpretable groups (any category under 3.5% of encounters was folded into "Other"):

| Group | ICD-9 codes | % of encounters (source paper's subset) |
|---|---|---|
| Circulatory | 390–459, 785 | 30.6% |
| Respiratory | 460–519, 786 | 13.6% |
| Digestive | 520–579, 787 | 9.3% |
| Diabetes | 250.xx | 8.2% |
| Injury | 800–999 | 6.7% |
| Musculoskeletal | 710–739 | 5.8% |
| Genitourinary | 580–629, 788 | 4.9% |
| Neoplasms | 140–239 | 3.6% |
| Other | everything else (symptoms/ill-defined, endocrine w/o diabetes, skin, infectious, mental, injury-external-cause, blood, nervous, pregnancy, sense organs, congenital) | 17.3% combined |

Using this exact scheme instead of inventing your own bucketing means your groups are directly comparable to a published, peer-reviewed analysis — a real credibility advantage if you cite it in your findings ("using the same diagnosis grouping as Strack et al. 2014").

## Known data quirks to check for during EDA

- [ ] Missing values are coded as the string `'?'`, not a true NaN — must be replaced before pandas will recognize them as missing
- [ ] Confirm your loaded CSV's missingness rates roughly match the table above (2% race, 97% weight, 52% payer_code, 53% medical_specialty) — if they're wildly different, you may have a different version/vintage of the file than the source paper used
- [ ] `patient_nbr` repeats — confirm how many encounters are repeat patients vs. first-time, decide the unit-of-analysis question above
- [ ] Confirm the `readmitted` class balance (`<30` vs. rest) in **your actual loaded file** before Phase 4 — the source paper's subset showed roughly 9-9.5% in their reduced 69,984-encounter set; the full 101,766-row version commonly distributed on Kaggle may differ since it includes repeat encounters. Compute it yourself, don't assume either number.
- [x] Discharge dispositions meaning "expired" or "hospice" — confirmed from `reference/IDS_mapping.csv`. `discharge_disposition_id` codes **11, 13, 14, 19, 20, 21** (Expired; Hospice/home; Hospice/medical facility; and three Medicaid-only expired/hospice variants). Applied via `df = df[~df['discharge_disposition_id'].isin([11,13,14,19,20,21])]` — **2,423 encounters excluded**, working set now 99,343 of the original 101,766.
