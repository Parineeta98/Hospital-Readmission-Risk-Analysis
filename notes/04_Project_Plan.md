This project has **one more phase than OASIS-2** (7 vs. 6) because of the new predictive-modeling step. - [x] **Phase 1 (Tue–Wed Jul 28–29):** Data foundations. Load CSV, replace `'?'` with real NaN, `.shape`/`.info()`/`.isnull().sum()`, decide and document: weight column (drop vs. keep), medical_specialty missingness, encounter-level vs. patient-level unit of analysis, exclude expired/hospice discharge dispositions from the readmission denominator. Descriptive stats by `readmitted`.
- [x] **Phase 2 (Thu–Fri Jul 30–31):** Seaborn EDA. Readmission rate by age band, by time_in_hospital, by num_medications, by prior utilization (number_inpatient/number_emergency). Confirm the `<30` class balance. Write findings notes as you go — don't wait until the end to document a pattern you noticed mid-analysis.
- [x] **Phase 3 (completed Aug 8) — REVISED Aug 1, her call, good instinct:** Deliberately lean schema (`fact_encounter` + `dim_diagnosis` only — OASIS-2 already proved multi-table star schema design, repeating it teaches a reviewer nothing new). Effort redirected from table-building to SQL depth: CTEs, window functions, and — the actual differentiator — 3 reusable **views** that formalize the Python `readmit_summary()` pattern (rate, n, margin of error) natively in SQL, ready for Power BI to connect to directly in Phase 5. See `01_Dataset_Schema.md` / EDA notes for the ICD-9 grouping scheme this finally puts to use. Also resolves a real open question from Phase 2: whether the `[20-30)` age spike is linked to a specific diagnosis category.
- [x] **Phase 4 (completed Aug 8):** Python predictive layer. Logistic regression predicting `readmitted <30` from encounter features. Evaluate on precision/recall/AUC, not accuracy alone — remind yourself why before you compute it (imbalanced target). Pull out top coefficients as candidate risk factors. Export encounter-level risk flags for use in the dashboard.
- [x] **Phase 5 (completed Aug 9):** Power BI dashboard connected via DirectQuery to Phase 3's SQL **views** (not a flat table import) — the realistic pattern: BI tool consumes a reusable analytical asset, not a one-off script's output. DAX measures for KPI cards (readmission rate, avg LOS, % flagged high-risk), breakdowns by diagnosis category/age/admission source, and a risk-flag visual driven by Phase 4's output.
- [x] **Phase 6 (Sat–Sun Aug 8–9, after 3pm):** Write the 3 findings + 3 actions stakeholder summary (`03_Findings_and_Actions.md`), hospital-operations audience, business language. Publish dashboard to Power BI Service. Push notebook + SQL + dashboard to GitHub with a README.
- [ ] **Phase 7 (Mon–Tue Aug 10–11):** Add the project to both portfolio sites, alongside OASIS-2 and the two earlier projects.
